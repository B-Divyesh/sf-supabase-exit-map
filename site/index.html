How it works

Inspect local project files

The CLI reads Supabase config, SQL migrations, and Edge Function source from the path you choose.

  1. Run the scan

    Point the CLI at a project root or its supabase directory.

  2. Review each dependency

    See file evidence, effort, replacement choices, and hosted-service limits.

  3. Plan the work

    Use the checklist before a restore test or cutover rehearsal.

Install and run

Run the CLI on your project

Install from source, then write a Markdown or JSON report for your planning work.

Install from source

Install the CLI from source on a machine with Rust.

cargo install --git \
  https://github.com/B-Divyesh/sf-supabase-exit-map

Run the bundled sample

--demo copies the sample into a new temporary directory and prints the report path.

supabase-exit-map --demo \
  --format markdown

Review populated findings

The sample identifies dependencies that change the order and cost of an exit.

01

Authentication

High effort · replace

Evidence config.toml:18 enables GitHub login.

  • List providers, sessions, redirects, and mail.
  • Choose an auth service or application auth.
02

Object storage

High effort · replace

Evidence files.sql:4 creates a bucket and policies.

  • Count and hash objects with read-only access.
  • Test signed URLs and restore behavior.
03

Realtime

Medium effort · replace

Evidence notes.sql:39 adds a publication.

  • Measure fan-out and connection count.
  • Test a replacement websocket route.
04

Edge Function

Medium effort · adapt

Evidence send-mail/index.ts:1 uses secrets and outbound fetch.

  • Record secret names and rotate values.
  • Add retry and timeout tests.
05

Row-level security

Medium effort · adapt

Evidence Policies call auth.uid().

  • Keep native Postgres RLS.
  • Replace Supabase claim shapes and roles.
06

Functions and triggers

Low effort · portable

Evidence Two routines and one trigger use PL/pgSQL.

  • Restore SQL in dependency order.
  • Audit owners and search paths.

What self-hosting does not provide

Open-source compatibility does not include managed backups, scaling, security response, or support.

Limits and privacy

What the CLI does not do

It helps you plan an exit. It does not migrate a live project or copy authentication data.

Check the live system separately

Dashboard settings, dynamic SQL, data size, sessions, and object bytes need read-only checks before cutover.
